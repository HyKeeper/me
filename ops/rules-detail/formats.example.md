# 格式模板（脱敏示例版）

> **这是 `AGENTS.md` 的附件，不是规则。** 规则本体在 `AGENTS.md`；本文件只放"某类文件长什么样"的样板，避免主文件被大段示例撑大。
>
> **何时读**：准备写对应类型的文件之前。不要凭记忆套格式。
>
> 📌 **本文件是脱敏示例版**：人名、条目 id 与经历均已替换为虚构占位。作者本地另有一份含真实条目的完整版，不随仓库发布。
>
> 立法理由与事故复盘另在 `rationale.md`（同样不随仓库发布）。

| 你要写 | 读哪一节 |
|---|---|
| 一条记忆条目 | §1 条目格式 |
| 追问用户 | §2 追问格式 |
| 时间线一行 | §3 时间线行格式 |

| 一份体检报告 | §6 体检格式 |

## 1. 条目格式

```markdown
---
topic: 老板是谁
updated: 2026-10-23T15:10:00+08:00
---

## current

- [id: boss-002] [spoken_at: 2026-10-23T15:05:00+08:00] [valid_from: 2026-10-23] [recorded_at: 2026-10-23T15:10:00+08:00]
  我的老板是张三，负责平台组，对我直接汇报。
  > evidence: "我老板叫张三，管平台的，我直接汇报给他"

## history

- [id: boss-001] [status: superseded] [spoken_at: 2026-09-01T10:00:00+08:00] [valid_from: 2025-06] [valid_until: 2026-10-23] [superseded_by: boss-002]
  我的老板是李四。
  > evidence: "李四是我老板"
```

**可选字段**（按需加，不强制）：`[confidence: high|medium|low]`、`[source: inference]`、`[vague: true]`、`[precision: month]`、`[clarified_at: ...]`、`[corrected_at: ...]`。

**CLARIFY 时**：`spoken_at` / `recorded_at` / `valid_from` **不动**，只追加 `[clarified_at]` 并在 evidence 下加 `> clarification:`。

## 2. 追问格式

```
⚠️ 需要你确认（可多选）：

记忆里（spoken_at: 2026-09-01 10:00，valid_from: 2025-06）：
  我的老板是李四。

本次输入（spoken_at: 2026-10-23 15:05）：
  我的老板是张三。

两条说法相差约 7 周，无法从时间线判断是更替还是更正。

请多选（可全选、可不选）：
  A. 换了老板。李四任期到 2026-10，张三从 2026-10 起接任
  B. 之前记错了。一直是张三，李四那条请作废
  C. 两个都是老板（如双线汇报），请说明各自负责什么
  D. 李四是 2025 年的老板，张三是现在的，两条都要保留为不同时期
  E. 以上都不对（请直接说）
```

**多选时，选中的每一条各自落到它该落的字段里，不要合并成一个笼统的"用户确认了"。**

## 3. 时间线行格式

```markdown
# 事件时间线

- 2025-06      [boss-001] valid_from：老板是李四
- 2026-09-01  [boss-001] spoken：用户首次口述"老板是李四"
- 2026-10-23  [boss-002] valid_from：老板换成张三（spoken 2026-10-23）
- 2026-10-23  [boss-001] valid_until：李四任期结束，移入 history
```

事件类型仅限：`spoken` / `valid_from` / `valid_until` / `superseded` / `corrected` / `unchanged`。

## 4. lesson 格式

```markdown
## 2026-10-23T15:10:00+08:00 | 相对时间换算

- **场景**：用户说"上个月老板换了"，处理时是 10 月 23 日。
- **我的判断**：换算成 9 月 23 日。
- **复盘**：中文"上个月"常指上一个自然月（9 月 1 日～30 日），而非"30 天前"。我可能锚错了。
- **建议**：在 §1 加一条——"中文模糊时间'上个月/上周'默认按自然月/自然周换算，用户纠正后按用户口径"。
- **触发提案**：待积累 3 次同类问题后提案。
```

## 5. 提案格式

```markdown
# PROPOSAL-001：中文模糊时间按自然月/自然周换算

- **状态**：待批准
- **优先级**：中
- **问题**：§1 只说"相对时间必须换算"，没规定"上个月"是 30 天前还是上一个自然月。
- **证据**：[lesson 2026-10-23]、[lesson 2026-11-05]、[lesson 2026-11-18]
- **建议**：在 §1 加一段规则，默认自然月/自然周，用户纠正后以用户口径为准。
- **影响**：只影响时间换算段，不动其他规则。
- **风险**：低。若用户口径不同，一句追问即可纠正。
```

## 6. 体检格式

```markdown
# 系统体检 2026-10-23T16:00:00+08:00

## 指标
- 记忆文件总数：42
- current 区 active 条目总数：42（应等于文件数）
- **异常：current 区出现多条 active 的文件**：2 个（people/boss.md、work/role.md）
- 缺 spoken_at 的条目：0
- valid_from 为 unknown 的条目：5（占比 12%）
- 本月冲突追问次数：3
- 本月 supersede 次数：7
- 未处理提案：1（PROPOSAL-001）

## 待用户确认
- people/boss.md 的 current 区有 2 条 active，疑似遗漏冲突处理：
  - boss-002（张三，2026-10-23）
  - boss-003（李四，2026-09-01 补录）
  请确认哪个是当前值。
```
