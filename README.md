# 个人记忆库 / Personal Memory

> 把一个人变成一份**可交接的档案**：让 AI 知道你，不只是知道你的资料，而是知道你会怎么选。

**核心理念：Markdown 是唯一事实源，没有任何数据库、向量库、专有格式。**

---

## 它解决什么问题

你的事实散落在微信、邮箱、招聘网站、银行 App、体检报告、和十几个 AI 对话里。每次开一个新对话，AI 都要重新认识你一次；每次换一个助手，你就得重讲一遍人生。

更麻烦的是：**你讲出来的永远只是"你是什么"，而不是"你会怎么选"。**

- 「月薪 N」→ 查得到
- 「有人给你 +40% 会不会跳」→ 查不到，只能猜

这个项目就是为后一个问题设计的。

---

## 它不是笔记软件

| 普通笔记 | 这里 |
|---|---|
| 一个话题一个文件，越写越长 | **一个属性一个文件**，`## current` 区**物理上只允许一条** |
| 改了就改了，看不到历史 | 旧值进 `history`，标 `superseded`，**永不删除** |
| 时间靠文件名 / 文件夹 | **三个时间字段必填**：说的时间、生效时间、记录时间 |
| 交给 AI，AI 用常理补空白 | 导出物**自带「我不知道什么」清单**，禁止 AI 猜 |

## 30 秒上手

```bash
git clone <this-repo> my-memory && cd my-memory
python3 scripts/init.py --name "你的名字"
```

然后把 `AGENTS.md` 交给任意 coding agent（Claude Code / Codex / Cursor / Pi …），开始灌：

```
我是张三，1990 年 3 月生，在上海做后端，2023 年入职某公司，月薪 3 万税前
```

它会自动拆成原子事实、换算时间、写入 `memory/`、并跑校验。

```bash
python3 scripts/check.py                    # 全库体检（结构/冲突/互洽）
python3 scripts/check.py --pre-text "跳槽"   # 写前检索：这条新事实会不会和旧值打架
python3 scripts/query.py "我在哪上班"         # 检索（同义词自动归一）
python3 scripts/query.py --as-of 2023-06    # 2023 年 6 月我是什么状态
python3 scripts/export.py                   # 生成 AI 化档案
```

## 运行环境

**零第三方依赖，纯标准库。** 不需要 `pip install`，不需要 GPU，不需要网络。

| 项 | 要求 | 说明 |
|---|---|---|
| Python | **>= 3.9** | 语法实测兼容到 3.8（`ast.parse(feature_version=...)` 全过），但 3.8 已 EOL，不保证。`scripts/init.py` 会在初始化时拦一道 |
| 第三方包 | **无** | 全部标准库：`pathlib` / `re` / `math` / `difflib` / `subprocess` / `unittest` |
| 操作系统 | Linux / macOS / Windows | 未使用 `fcntl`、`pwd`、`chown`、`os.fork` 等 Unix-only API |
| 文件编码 | **UTF-8** | 所有 `read_text` / `write_text` 都显式带 `encoding="utf-8"`，不依赖系统 locale |
| 文件名 | 支持中文目录名 | 如 `memory/people/<本人>/`。排序用 Unicode 码点，与 locale 无关，结果可复现 |
| 内存 / 磁盘 | 可忽略 | 千条级语料，索引全部常驻内存 < 10 MB |
| 网络 | **不需要** | 无模型下载、无 embedding 服务、无外部 API |

性能实测（48 条条目 / 3500 token / 620 条归一表）：

```
索引构建 12 ms ｜ 单次查询 0.39 ms ｜ 全库两两 0.53 ms
```

> 这组数字随语料增长。**归一表膨胀是主要成本**：从最初的 65 条涨到 620 条后，
> `tokenize()` 每次都要遍历整张表做替换，耗时涨了约一个数量级。语料本身增长反而次要。

### 时区：当前唯一的硬环境耦合

时间戳校验是 **`+08:00` 硬编码**在 `scripts/check.py` 的 `TS_OK` 正则里的，而 `memory/_config.md`
虽然有 `timezone` 配置项，**校验逻辑并没有读它**。

- 在中国时区使用：无影响。
- 非 `+08:00` 环境：所有条目都会被判为 ERROR。需要改 `scripts/check.py` 里的 `TS_OK`，
  或把 `timezone` 配置真正接进校验逻辑。

这是开源化前明确的待办，不是设计意图。放在这里而不是藏进 issue，是因为**使用者有权在 clone 之前就知道**。

## 测试

```bash
python3 -m unittest discover -s tests -t tests
```

87 个测试，**零测试依赖**（标准库 unittest），约 0.15 秒跑完。

覆盖的是**规则语义**而不是行数：四档时间判定、`current` 单条不变量、派生值检测、
同义词归一、十层归类、配置默认值回落、init 幂等性 —— 每条规则都有「能抓到」和「不误报」两个方向。

它自己也验证过有效性：人为植入 5 个 bug（放宽 current 检查、改坏 `<=` 语义、
关掉同义词归一、让 as_of 忽略 valid_until、跳过 evidence 检查），**5 个全部被测试抓到**。

## 目录结构

```
AGENTS.md                # 给 agent 的规则书（宪法级 10 条不可自行修改）
memory/                  # 事实库，全是 Markdown
  _config.md             # 实例配置（你自己填，别提交）
  _aliases.md            # 实体别名：某俗称 = 某标准名
  _synonyms.md           # 概念归一：医保 → 社保 → 五险一金
  people/<人名>/         # 一人一子目录，属性一文件一属性
  work/ preferences/ health/ projects/ misc/
  timeline/events.md     # 事件流，append-only
ops/                     # agent 的自我维护区：教训、提案、变更日志、体检
scripts/                 # 零依赖工具链（7 个脚本，无第三方包）
tests/                   # 78 个单元测试（标准库 unittest）
```

## 四条铁律

1. **Markdown 是唯一事实源。** 不引入数据库。所有索引可从 `memory/` 重建，可随时删除。
2. **不删除，只标记。** 旧值移入 `history` 并标 `superseded`，条目永不从文件消失。
3. **三个时间字段必填。** `spoken_at`（你说的时刻）、`valid_from`（事实生效时刻）、`recorded_at`（写入时刻）。任何一条缺失都不允许写入。
4. **`## current` 只允许一条 active。** 写入后必须自检，违反即回滚。

> 第 4 条是整个设计的关键：**冲突在物理上可见。** 因为一个文件只能放一条当前值，覆盖旧值这个动作**避不开**——agent 必须先读、必须先决定这条新信息是补充、更替还是矛盾。

## 十层导出（AI 化的核心）

`export.py` 产出的不是事实清单，是十层结构：

| # | 层 | 回答 |
|---|---|---|
| 1 | 身份锚点 | 我是谁 |
| 2 | **决策函数** | 遇事我怎么选 |
| 3 | **红线与雷区** | 我绝不接受什么 |
| 4 | 资源与约束 | 我有什么、被什么绑住 |
| 5 | 关系网络 | 谁是谁、能求什么 |
| 6 | 时间结构 | 我的一天/一周/一年 |
| 7 | 目标与进度 | 我在往哪走 |
| 8 | **语言指纹** | 我怎么说话（从原话反向统计，非虚构） |
| 9 | **已知空洞** | 我不知道什么（脚本自动生成） |
| 10 | 事实附注 | 原始条目 |

**第 9 层是硬要求。** AI 化最大的风险不是信息少，是 AI 自信地拿常理填空而你不自知。所以导出物必须自带一份"我还不知道什么"的清单。

第 8 层也不是玄学：它统计你原话的句长、标点习惯、是否用句号、中英混排方式。**给一段模仿你口吻的文字加句号，就不像你了**——这是事实清单永远给不了的东西。

## 通用 vs 个人：三层分离

这套系统刻意把「引擎」和「某个人的数据」切开。开源出去的是左边，右边永远不进仓库：

| 层 | 通用（进仓库） | 个人（.gitignore） |
|---|---|---|
| 规则 | `AGENTS.md`（十层模型、三时间字段、冲突裁决） | — |
| 代码 | `scripts/` 全部逻辑，**零硬编码个人事实** | — |
| 词表 | 算法：向量化、归一、排序 | `_synonyms.md`（语义概念）`_aliases.md`（实体别名） |
| 参数 | 计算方式（工资×比例×2） | `misc/北京社保公积金参数.md`（地区政策数字） |
| 数据 | — | `memory/` 全部内容 |

**判定准则：如果某个字符串换成另一个人就不成立，它就不许出现在代码或通用模板里。**

首次使用时按模板初始化：

```bash
cp memory/_config.example.md   memory/_config.md
cp memory/_synonyms.example.md memory/_synonyms.md
cp memory/_aliases.example.md  memory/_aliases.md
```

（`_synonyms.md` 放**语义概念**——工作/薪资/社保这类谁都用得上的词；`_aliases.md` 放**实体**——公司小名、人名、地名。前者可通用，后者因人而异，混在一起既会过拟合也会泄漏。）

## 隐私警告（请先读这段）

**这个仓库里装的是一个人的全部人生。** 包括薪资、家庭、健康、对人和事的真实评价。

- `.gitignore` 已默认排除 `memory/` 全部内容和 `export-*.md`，只保留模板。
- **提交前务必 `git status` 确认没有把 `memory/` 带上去。**
- 想要版本控制又不想外泄：用**私有仓库**，或把 `memory/` 放在仓库外、用软链接接入。
- 开源出去的应该是**系统**，不是**数据**。

## 设计取舍（为什么不那么做）

**为什么不用数据库 / SQLite？**
一个人的记忆是可读的、需要 diff 的、需要 git 的。用 SQLite 你看不出「他上周把这个改成那个」，Markdown 一个 `git diff` 就能看见。代价是没有唯一索引做事务约束，所以用 `check.py` 事后校验 + agent 流程强制。

**为什么不用 embedding / RAG？**
本项目的使用者可能在没有任何 GPU、没有 embedding 服务的机器上。而语料规模是**千条级**——这个量级上字符 bigram TF-IDF 的检索质量与轻量 embedding 相当，延迟低两个数量级（48 条规模下：建索引 12ms，单次查询 0.39ms）。真正的语义缺口用 `_synonyms.md` 概念归一补，比下载 500MB 模型便宜得多。

**为什么不用自动冲突检测的相似度阈值？**
实测过：全库最高相似的一对是「某系统的职责描述」和「同一系统的知识描述」，余弦 0.37 —— 完全合理，不是冲突。**相似 ≠ 冲突**。所以语义能力只做候选生成，裁决权始终在人 / agent，阈值从不自动告警。

## 已知局限（诚实清单）

- `_synonyms.md` 是检索质量的天花板：你的说法没被覆盖就检索不到。
- 十层里的第 2、3 层无法自动生成，只能靠对话问出来。
- 冲突裁决依赖 agent 的判断力，脚本只能抓结构性错误。
- **同一时刻只应有一个 agent 在写。** 这不是「缺了并发控制」——这是个单用户单进程的 CLI 工具，
  上文件锁属于过度工程。真开了两个终端同时写，覆盖问题由 git 兜底：`git diff` 会明确告诉你谁覆盖了谁。
- 检索只针对中文 + 英文优化（中文 bigram / 英文整词），其他语言退化为纯字符切分。
